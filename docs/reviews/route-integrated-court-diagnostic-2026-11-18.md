# Hub court integrated material diagnostic — 18 November 2026

**Verdict: rejected.** This source experiment started from local `main` at `688fa3a9f6bddcf25138c2d9d5a3678e1197aaeb` in `work/route-integrated-court-20261118`. All runtime edits were reverted before this report commit. The accepted warm packed-earth path remains the game source.

The trial hid only the hub's `village_dirt_` decorative meshes from rendering, left those map surfaces in the authoritative data, and painted a route-distance field directly on the existing grass court meshes. It sampled the unchanged route graph (10 lower and 18 upper segments), converted the Godot 3D positions back to logical map coordinates, and blended the project grass/dirt textures at pixel scale. No walkable floor, collision, stairs, route graph, ground height, asset, or material license changed. The purpose was to avoid the little fragments that clipping separate dirt polygons repeatedly produced.

The focused existing `village-ground.test.ts` passed 6/6, including 2,000-plus unchanged walkability samples. `npm run typecheck` passed. A fresh Godot 4.7.2 Compatibility editor import first found an erroneous `PackedVector2Array.get_bounding_rect()` call; it was corrected to an explicit `Rect2.expand()` loop before the valid renders. The second and later editor imports and three non-headless native six-frame runs at 667×375 and 844×390 printed `TERRAIN FACETS RENDER PASS` without `SCRIPT ERROR` or `ERROR`. Full results/logs are ignored local files under `artifacts/godot/route-integrated-court*` and `.runtime/route-integrated-court-*.log` in the experiment worktree. These static Apple M2 captures do not prove browser, Windows, Samsung S23, or motion performance.

A later improvement needs authored *site composition*: a grounded stone/stair landing and house/dock thresholds arranged with planted edges, judged in traversal at actual game size. More global width, color or noise variations of this same route field are unlikely to meet the target.
