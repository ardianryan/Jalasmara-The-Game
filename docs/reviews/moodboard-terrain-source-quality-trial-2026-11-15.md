# Terrain stone-detail trial rejected

Date: 15 November 2026. Branch: `work/terrain-source-quality`, based on `c3575c5`. This report records a visual trial; **no runtime change is offered for integration**.

The full moodboard target still calls for a more organic island bank and more deliberate rock art. The current hub lower coast already has a naturalized top contour and connected faceted shoulder. At the actual 667×375 game size, its stone faces remain pale and broad. Adding more geometry to the rear ocean support was previously rejected in [the reef geology review](moodboard-reef-geology-2026-11-15.md), and the accepted [terrain facet pass](moodboard-terrain-edges-2026-11-15.md) already split the largest rectangular faces.

I tried a code-authored, world-aligned 5-unit pixel grain and sparse short fissures inside the existing stone material (`LandMaterials.gd`, `kind == 3`). The trial added no atlas, mesh, material, collider, or authoring dependency. Godot 4.7.2 Compatibility rendered the actual hub lower coast, hub central stairs, and forest upper bank at both 667×375 and 844×390 before and after. The candidate's stone detail is barely visible at those sizes and does not materially change the pale panel reading or island silhouette. The trial was therefore reverted. Diagnostic original PNGs and logs are in this worktree's ignored `artifacts/godot/terrain-source-quality/{before,after}/` and `.runtime/terrain-*.log`; they are not release assets. The lower-coast 667×375 PNG hashes are baseline `50894ebe91cd560305263913a5f300988a0cf27589d5981b15240fd045fb7ab1` and candidate `462ce7964470d30d83a3e2a7521c98f5dfbb9fbb4c8d3af64adb12d5e369ed02`.

The second Godot editor import was clean after the first pass generated missing font cache entries. Both native render passes printed `TERRAIN FACETS RENDER PASS` without `SCRIPT ERROR` or `ERROR`. After reverting, focused `terrain-facets.gd` and `natural-terrain-edges.gd` passed; the latter reports eight surfaces, 512 active nodes, 516 excluded segments, and 251 supported nodes without authoritative world mutation. There was no browser, exported PCK, Windows, Samsung S23, or measured GPU frame-time test in this lane.

The next terrain pass should target the visible source silhouette and cohesive stone value ramp together, at actual game scale: top polygon contour, connected shoulder faces, and the existing 32×32 limestone microtexture as one composition. Keep the dock and stair mouths clear, keep authoritative floor polygons and collision unchanged, and compare same-camera frames at 667×375 and 844×390 before accepting. Another subtle per-fragment noise layer would repeat this failed trial.

Tools actually used: Git worktree, repository-authored Godot code, Godot 4.7.2 Compatibility native/headless renderer and focused tests. The existing limestone asset was only inspected; the owner's moodboard and external tools supplied no distributed pixels or code. No asset provenance or third-party license changes are needed. This branch is local only; it was not pushed, merged, exported, or staged.
