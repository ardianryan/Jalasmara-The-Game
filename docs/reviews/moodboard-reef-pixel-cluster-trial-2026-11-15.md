# Reef pixel-cluster trial — rejected at gameplay scale

Date: 15 November 2026. Isolated branch: `work/reef-pixel-quality`, based on `9392ec9b3b6c9f46df3b7750d8a28777d9a45c56`. **This is a visual research result, not a runtime change or staging release.**

The owner wants the underwater world to reach the colorful, clear pixel-art moodboard. The current coral clusters are 724 px wide per variant and render much smaller in the game. I tested two bounded replacements at unchanged `ReefGrowth` locations and sizes: (1) three 64×64 silhouettes drawn pixel-by-pixel with Pillow primitives and a small project palette, and (2) three 128×112 cells derived from the project's existing coral atlas with a 48-color palette and hard alpha. The cave backwall, ocean material, parallax, collision, ten gameplay species, oxygen, fish, and target logic were untouched in both trials.

[The actual-size comparison](../visual/reef-pixel-trials-667x375-20261115.png) contains the same camera at the shallow reef and cave passage for the existing source and both trials, without rescaling the screenshots. Its SHA-256 is `87719291b3b5b72c4b1cb30643786a4ae24265e696db2db2597cac346cfa0a83` (473,124 bytes). The source screenshots were also captured at 844×390 in the isolated worktree, then removed with that worktree after review; the curated comparison remains.

The 64 px authored plant has a legible hard-pixel silhouette, but its flat fan, base and tube geometry look disconnected from the detailed limestone and existing Nala/fish artwork. At 667×375 it changed 2.67% of the reef frame and 4.87% of the passage frame by more than 8 RGB levels; the change is visible but lower-quality. The 128 px source-derived trial keeps the original form, but at gameplay size it is effectively indistinguishable from the existing plant, changing 1.24% of the reef frame and 2.67% of the passage frame by the same measure. It does not improve the dominant painterly rock/backdrop mismatch. **Neither trial was accepted.** The runtime source, original atlas and art provenance remain identical to base; rejected PNGs and the authoring script were removed from the worktree. The gallery comparison is retained only as development evidence.

Verification: Godot 4.7.2 Compatibility rendered four native full-scene frames for each variant at 667×375 and 844×390, with unchanged fixture oxygen 77 and coins 700. All three render logs reported `OCEAN SHAFT RENDER PASS` and no `SCRIPT ERROR` or `ERROR`. The first editor import in a fresh worktree printed transient missing font-cache errors; a second editor import finished with no such messages. This is native Apple M2 visual evidence, not a Windows/Samsung S23 GPU benchmark, moving gameplay review, or proof of full moodboard parity. No full world/API/build suite was needed because no production source was retained.

Tools actually used: project Godot 4.7.2 Compatibility, Python 3/Pillow for temporary authoring and image comparison. All temporary pixels came from original code geometry or the project's own coral asset; no third-party moodboard pixels, external repository code or new runtime dependency entered the game. The source asset remains under the Jalasmara artwork terms in `LICENSE` section 2.

Next visual work should address the **karst and midground composition as a coordinated scene**, then match coral pixel density to that art at actual gameplay size. A smaller atlas by itself is insufficient. Keep the existing alpha-edge threshold and preserve target visibility, collision and mobile frame pacing. Capture before/after at matching camera/time and test moving browser/device scenes before staging.
