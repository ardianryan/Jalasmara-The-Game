# Cold public game startup: transfer diagnosis

## Result

The first cold browser startup for source `0a94d985445f9e59e44ba6f126b7645f9a1b594d` and CI PCK `9e84afe2fd3a49a370240571416f45b16f354df6557db1885dcbbca2b8f01fb8` did not reach Godot READY within the 120-second smoke deadline. The final periodic trace at 110.9 seconds showed 37% of 112.5 MB delivered. This is a public-transfer limitation; the trace does not show a game script error or an invalid PCK response. Fixture cleanup reported zero remaining players, receipts, shifts and keys.

Evidence: `.runtime/moodboard-ci-43718958769/cold-smoke.log` in the integrator worktree, generated by the public startup trace in `scripts/staging-plan06-smoke.mjs`. The file is an ignored local test artifact, not a production asset.

All recorded PCK responses had HTTP 200 and the expected public endpoint; the aborts were client-side `net::ERR_ABORTED`. The trace shows the first part receiving 114,688 bytes before its 30-second abort. The new head-of-line hedge could not repair a connection where both the primary and hedge were starved. It also could not overcome the parallel 39.5 MB WASM transfer. The browser reached only 4 of the 70 PCK parts after about 111 seconds. Even eliminating every repeated attempt would not establish a 120-second READY result from this trace: the remaining 66 parts were still required, and Godot initialization had not begun. This is an inference from the observed transfer, not a measured upper bound on the host's capacity.

## Loader assessment

`scripts/pck-stream.mjs` uses four primary 1 MiB requests, at most one hedge for the blocking part, exact response metadata and SHA-256 validation, and a 30-second absolute timeout per attempt. The timeout does cause cold-transfer retry churn when a response body is trickling under load. A larger timeout or inactivity-based timeout could preserve partial progress, but neither would make the public path deliver the remaining 66 MiB within the observed deadline. Increasing concurrency or adding more hedges would risk worsening contention and duplicate transfer. No loader change is accepted from this investigation because no controlled cold browser comparison demonstrates a READY improvement.

The next useful measurement is an isolated transfer comparison using the exact CI PCK: simultaneous WASM/PCK start, PCK-only start, and a direct VPS-origin versus public-host request, with response-body rate and abort count recorded. If the public path alone is slow, inspect its reverse proxy/CDN HTTP/2 buffering and bandwidth settings before changing the loader again. Separately, use the PCK inventory to identify production assets that can be safely removed or deferred, with source/provenance and native rendering review. These are follow-up tasks; this report makes no server or asset change.
