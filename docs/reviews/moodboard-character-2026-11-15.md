# Nala swim-cycle refinement candidate — 15 November 2026

The source-derived diver had three poses reused in an eight-step travel rhythm. The 112-pixel silhouette was already readable, but long holds on identical fins made the kick feel mechanical. This bounded candidate gives each travel phase a distinct pixel frame while keeping the torso, face, outfit identity and detachable equipment unchanged.

## Changes and provenance

- `tools/player-swim/build_swim_atlas.py` now builds an eight-frame 896×112 strip for each of the four existing appearances. The source poses follow `0,0,1,1,2,2,1,0`; five variants bend only the free fin tips by at most two source pixels. The body and leg roots are byte-identical to their parent pose beyond the 36-pixel fin region. The original project portrait sources are unchanged.
- `CharacterVisual.gd` selects the eight atlas cells using **actual distance swum**, preserving its existing stopped level-fin pose, idle bob, turn pitch, shot recoil, hit reaction, reduced-motion behavior and left-facing flip. `OceanActors.gd` and independent 3D tank/net/launcher nodes are unchanged.
- The four PNGs and `player-swim-v2/provenance.json` were regenerated by the offline Python/Pillow authoring tool; the manifest records every source and output SHA-256, source-pose order and fin-tip offsets. No external moodboard image, AI service or new runtime dependency was used. These are derivatives of the project's existing character art under its artwork terms in `LICENSE`, not MIT-licensed tool artwork.

The source change is commit `2fdcc37` on `work/moodboard-character-20261115`, based on `06e0a82eb6dddfd681255f630036371dacaa7c11`. It is a local integration candidate; it has **not** been pushed, merged, exported or released to staging.

The test checks source/output hashes, binary alpha, visor detail, eight unique frames, one connected silhouette per frame and untouched body pixels in fin-flex variants. `git diff --check` passed.
- Godot 4.7.2 headless `character-swim-reaction.gd` and `character-outfits.gd` passed. `player-locomotion.gd` first logged a `SCRIPT ERROR` because this isolated worktree lacked ignored `.runtime/world-map.json`; after copying the same fixture from the main worktree, the full test passed cleanly. Native `swim-reaction-render.gd` passed on Apple M2/OpenGL. No Web export, browser, Windows or Samsung S23 test was run in this branch.

The visual gain is **modest**: the fin transitions are less frozen, and the native sequence shows no detached foot or popping torso, but the artwork still derives from only three original body poses in one facing. This does **not** establish eight-way swimming, match the full cozy pixel moodboard, or prove motion at 667×375 on a physical device. The integrator should run the combined world suite and inspect a fresh native/browser reef capture after cherry-picking; reject the candidate if adjacent frames visibly jitter at actual game scale. Larger source-quality directional animation and matching world/gear detail remain separate art work.
