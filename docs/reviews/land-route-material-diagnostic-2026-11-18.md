# Land route material diagnostic — 18 November 2026

Source base: `4fec3d8410ea4368a4dfe86e4b868ba753b4ee90`. This isolated trial tested whether the decorative dirt routes could read closer to the comfy pixel-art target through material changes alone. It did not alter the authored path footprint, walkable floor, collision, terrain, or server state. **Both source candidates were rejected and reverted.** This package contains evidence and diagnosis only; it has not been built, pushed, or staged.

The candidate reused the existing nearest-sampled 32×32 dirt texture and spatial shader. A separate material applied only to nonwalkable dirt surfaces lowered high-frequency microtexture strength from `0.55` to `0.32` and added broad, continuous world-space soil tones. It did not add a shader, texture, geometry, or draw node. The first dark-end multiplier (`.86/.89/.91`) gave the hub path more depth but created an unnatural dark blotch below the forest bridge. A second multiplier (`.93/.95/.96`) removed most of that blotch, yet the change was barely visible at game size. The path still reads as a wide orange strip with hard segment joins and disconnected narrow strokes near the house and dock. Material shading cannot repair those silhouette and layout defects.

The [hub 667×375 comparison](../visual/land-route-material-diagnostic-20261118/hub-lower-coast-ab-667x375.png) and [forest 667×375 comparison](../visual/land-route-material-diagnostic-20261118/forest-upper-west-bank-ab-667x375.png) show base on the left and tuned candidate on the right, each at original capture size. The same-camera 844×390 frames, first candidate frames, logs, and six-frame results are retained as ignored local artifacts under `artifacts/godot/land-route-{baseline,candidate,tuned,comparison}-20261118/` in this trial worktree. The 844×390 originals were independently reviewed before rejection.

Godot `4.7.2.stable.official.ed1daf0bf` Compatibility on Apple M2 rendered all six hub/forest day frames at both sizes for baseline, first candidate, and tuned candidate. Each final render printed `TERRAIN FACETS RENDER PASS` and had no `SCRIPT ERROR` or `ERROR:`. The focused temporary material fixture passed after correcting its handling of unset Godot shader parameters; the fixture and runtime change were removed with the rejected candidate. A fresh-worktree editor import briefly logged missing font cache resources; the second import and subsequent tests/renders were clean. These native stills do not establish Windows/Android frame pacing.

The next useful pass must revise authored route widths and joins at the lower house, central stairs, and forest bridge, and remove clipped remnants in a way that retains a continuous walking corridor. Pair that geometry work with restrained ground material variation, then test actual movement and native/Web frames. Repeating a global dirt tint, stronger microtexture, or broader alpha dither will not meet the target. Tools actually used: project Godot renderer, shared `WORLD` map generation in Node, and Pillow for contact sheets. No third-party asset was copied or licensed.
