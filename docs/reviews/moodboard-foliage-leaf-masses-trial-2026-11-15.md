# Foliage leaf-mass trial — rejected

This second isolated source-art trial attempted to group the existing broadleaf canopy's tiny green highlights into larger, intentional clusters while retaining its branches. **It is not accepted into the game.** At the actual 667×375 forest view the direct four-tone version made the foreground tree look flat and detached from neighboring canopies. A moderated version kept more texture, but made that tree softer rather than more legible. The 844×390 hub view barely changed. Neither result reaches the approved pixel-art moodboard.

The experiment used only the original project atlas `client-godot/resources/art/land-foliage-v1.png` (1536×1024 RGBA; SHA-256 `1f07437f9ff5f9cbc063c191904eecf734ffad859b3daf6f0fccf177c8aa4564`). Its six 512×512 cells, alpha plane, atlas regions, UV positions, source sprite count, and runtime draw calls were unchanged. Pillow and NumPy in a temporary CPU script derived a low-frequency luminance field from the original pixels in the two broadleaf cells, assigned four restrained green tones within opaque foliage, and retained the original branch colors. The direct candidate was 2,066,391 bytes, SHA-256 `946c5883a19b1f1d206e73c672925a2e545200a3c745f260cbcfff09931a82d6`. The final 45% blend toward that candidate was 2,199,023 bytes, SHA-256 `4f1b37869b975bfa690ff7a95dd180ed362cd3e8ac7f22826219b3ac85560fbf`. Both candidates remained in temporary `/tmp` files; no production asset was replaced. No external or moodboard pixel was copied; no new runtime dependency or license was introduced.

Godot 4.7.2 Compatibility on Apple M2 rendered the same land scene at 667×375 and 844×390 with a native atlas substitution on existing Sprite3D nodes: 136 in the forest and 53 in the hub. The [667×375 before/after sheet](../visual/foliage-leaf-masses-rejected-20261115.png) shows the moderated candidate at its actual game size (sheet SHA-256 `018c73c4294d1668a1d623ca82a8d6fae5c8b05106a34cd916343c80d046c90d`). Pixels differing by more than 16/255 in any RGB channel were 1.549% of the 667×375 forest screen and 1.252% at 844×390; hub differences were only 0.088% and 0.079%. The first import in the fresh worktree had a transient font-cache error; the second import and native render log had no `SCRIPT ERROR` or `ERROR`. These are source/native visual checks, not browser or physical-device FPS evidence.

This confirms that automatic cluster-tone remapping can visibly change a canopy yet fail to improve its form. The next viable route is to draw deliberate leaf masses and branch openings by hand at the actual displayed canopy scale, compare every affected tree and palm rather than only one close tree, and preserve the existing occlusion and mobile sprite budget. The original atlas remains the production choice. No build, push, merge, or staging activation was performed from this branch.
