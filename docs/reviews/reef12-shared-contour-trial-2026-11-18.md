# Reef 12 shared-contour trial — 18 November 2026

**Decision: rejected.** This package contains visual evidence only. No ocean terrain, collision, navigation, coral placement, or gameplay source changed on `main` as a result of the trial. The isolated branch started from `9c5263a`.

The existing `WORLD.terrain[12]` is a shallow 1,844 × 160 unit shelf beneath the waste valve at `(4660, 2630)`. Its 13-point `terrainContours[12]` creates a nearly level upper edge and one broad dark front face. `TerrainGeometry.gd` renders that shared contour, while the server uses the same source for position clearance. The defect is visible in the [667 × 375 baseline](../visual/reef-contour-parity-20261118/baseline-667x375.png) and [844 × 390 baseline](../visual/reef-contour-parity-20261118/baseline-844x390.png).

First I tried a 28-point shared contour with two smooth eroded crowns, contained within the original rectangle. A CPU test passed non-crossing, bounds, a clear approach to the valve, and clearance at all six boss resonance points. The native full-ocean render consumed roughly 12% CPU but produced no first 667 × 375 frame after two minutes, so I stopped it. This candidate is rejected on verification/performance grounds. The native log did not identify a script error or pinpoint where its mesh construction/render stalled.

I then kept the original 13 vertices, lowering only the two broad middle crest points to form a cove. The CPU test passed the same geometry and server-clearance checks; `ocean-platform06.gd` passed headless. The native render completed at both sizes by starting each viewport in a separate process, avoiding the fixture's known stall when resizing from 667 to 844 during one run. The [667 × 375 candidate](../visual/reef-contour-parity-20261118/rejected-cove-667x375.png) and [844 × 390 candidate](../visual/reef-contour-parity-20261118/rejected-cove-844x390.png) replace the horizontal dark edge with one long diagonal teal wedge. On the right, the auto-placed corals read as floating above that lowered edge. That is visually worse than the source slab, so the candidate and its temporary CPU test were reverted. A passing geometry test did not establish composition quality.

The next attempt should keep the existing 13-point authoritative contour, then build decorative geology **inside its blocked area** that obscures the straight line without inventing a swim gap. Rework face UV/lighting and coral mounting together if needed, and verify that the result has neither a false platform nor detached coral at both native sizes. Perturbing the upper contour alone exposes flat teal water or a straight wedge rather than a believable 2.5D reef. This is a hypothesis from the paired images, not proof of an isolated shader bug; it is not implemented in this package.
