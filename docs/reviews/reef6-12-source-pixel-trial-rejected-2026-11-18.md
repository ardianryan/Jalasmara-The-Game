# Reef 6/12 source-pixel face trial — rejected

**Decision:** do not merge the trial runtime, generated PNG, or authoring script. The native pictures are visibly worse than the current scene. The committed package contains this diagnosis and six small proof images only.

The isolated branch `work/reef6-12-source-pixel-junction-20261118` started at local main `cd8214e`. The trial made a 512×512 unique pigment source by nearest-grid sampling and 72-color quantization of the project's own `ocean-terrain-atlas.png` first limestone cell. Deterministic pixel strokes, pore rims and growth clusters were drawn on that result. A visual-only, noncolliding unified mesh replaced ReefRelief6 and ReefRelief12, sampled this image in one world-aligned UV domain over x4200–6144/y950–3100, and used a hand-scalloped west and lower edge. The authoritative `terrainContours`, targets, valve, coral positions, fish and server collision were unchanged. The source atlas SHA-256 was `4505f32bf214c2929d5c3eb05a85c01d473d9b8597ed5f96fc3fde974ea946b6`.

This result rules out scaling one atlas crop over both volumes. The original `TerrainGeometry._build_reef` uses terrace bands, independent depth, normal/tint, and project-wide atlas variation to make local limestone relief. The trial removed both volumes and replaced their front with a nearly coplanar face. Stretching one 512×512 source over roughly 1,944×2,150 world units also enlarged porous motifs, while the added pixel strokes aligned into ruler-like lines. `OceanGeology` still generated rectangle-derived rear roots, and `OceanBackdrop` still moved its far/mid/near cards independently, so neither layer met the new silhouette. Coral pivots still existed, but their visible bases no longer sat on convincing rock. A valid polygon, a unique texture, and a combined UV domain therefore did not create a believable 2.5D junction.

## Verification and limits

Godot 4.7.2 Compatibility on Apple M2 rendered all six original-size frames, exited 0 and reported oxygen 77/coins 700 with coral pivots present. Cold editor import emitted seven transient missing-font-cache/theme errors; the second import had no `SCRIPT ERROR` or `ERROR:`. The temporary `geographic-map-check.mjs` invocation wrote `.runtime/world-map.json` but could not spawn its default Godot binary; native fixture used the explicit local Godot binary and succeeded. This was a visual rejection, so no full world/build/API/browser or moving sweep was run. The static camera trio already exposes the failed geometry and a sweep cannot rescue it.

Full PNGs remain ignored locally in `artifacts/godot/reef-source-candidate/`; this path disappears when the worktree is cleaned. The committed WebPs are smaller visual documentation, not game art.

**Next source-art requirement:** produce a new authored *multi-surface* limestone formation whose separate top, front, side, underside and recessed cave pixels meet at shared world-space edges and UVs. The form must be composed alongside its rear stratum and background mask, with irregular *volume* and value hierarchy; the gameplay lip must remain readable and coral mounts must appear rooted. Do not merely stretch a limestone crop, generate one giant planar face, or append another transparent strip. Capture a moving 4470→5500 sweep at both viewports only after stills pass. A source artist or a dedicated modular pixel-mesh authoring workflow is warranted before another integration attempt.

**Provenance:** temporary pixels came only from the project-owned atlas; Python/Pillow authored the trial image and converted proof frames. No moodboard pixels, external art, or third-party runtime library were used. The rejected generator, PNG, render fixture and runtime edits were removed from the worktree before commit.
