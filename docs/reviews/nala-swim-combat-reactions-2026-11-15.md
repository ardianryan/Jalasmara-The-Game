# Nala swim and combat-reaction candidate — 15 November 2026

## Scope and source

The owner reported that Nala's swimming was stiff, shooting and damage had no character reaction, and the gear/pixels were unclear against the moodboard. The change in source `abfe2d4beea359afd12875ef2671a954c2ea22ea` changes the Godot runtime; it does not change server combat rules, collision, terrain, camera, or the seven accepted village-resident sprites. The prior staging package was Gito source `3a18ee52`, CI PCK `9eefa0d0e8573043f14ad28ffab0c414e0c767ef402d020d27cc550fe7f18b55`, image `fdd65aba4615`.

`CharacterVisual.gd` now selects compact 3-pose swim strips and advances the kick using actual distance travelled. Idle holds a level-fin pose; vertical velocity pitches the body slightly. The neutralizer input starts a short body and launcher recoil immediately, with a muzzle flash and a capsule path after server confirmation. A hazard or boss projectile briefly tints/squashes Nala and recovers automatically. `OceanActors.gd` copies the visual rotation and tint to the actual 3D sprite. Reduced-motion mode removes the idle bob and limits recoil. `RenderQuality.gd` starts touch devices on Balanced, offers Sharp after sustained 56 FPS, and drops back after sustained low FPS; this is a policy change, not a measured S23 improvement.

The four derived 336×112 swim strips come only from the existing four project portraits; `tools/player-swim/build_swim_atlas.py` uses local Pillow, a shared 64-color palette per appearance, alpha threshold and nearest runtime sampling. `provenance.json` stores source/output hashes. The net and neutralizer plates are original 48×32 code-authored pixels. No moodboard or external UI/tool art entered the game. Project artwork terms in `LICENSE` section 2 remain applicable. Python/Pillow is offline authoring only, Godot 4.7.2 Compatibility is runtime; no new runtime dependency or upstream license was added.
