# Land route width and join diagnostic — 18 November 2026

Source base: `7c9936a`. The visual candidate was **rejected and reverted**. This package contains only this report and original-size comparisons; no runtime code was retained, built for Web, or staged.

The 72-unit dirt paint in `village-ground.ts` is composed from separate segment quads and octagonal join caps, then clipped around stairs, buildings, and gardens. The server-owned walkable courts and route centerlines are separate. After the earlier whole-route union created a broad flat orange strip and a material-only pass left hard joins intact, this trial tested a gentler composition: 12-sided caps, discarding clipped fragments below 900 square units, and a 12-unit soft edge on village dirt instead of the current 7-unit edge. The authored 72-unit footprint, route centerlines, collision and connector geometry remained unchanged. A separate CPU-only narrower visual-width experiment (60, 64 and 68 units) split the lower-court painted route into two components; only the 72-unit version reached native render.

The CPU checks showed that the 72-unit candidate's upper and lower court paint each formed one connected polygon union, with only small detached fragments removed. The focused village-ground test passed 6/6 and `npm run typecheck` passed. Godot 4.7.2 Compatibility on Apple M2 rendered six actual-world frames at 667×375 and 844×390 for both baseline and candidate. Both runs printed `TERRAIN FACETS RENDER PASS` with no `SCRIPT ERROR` or `ERROR:`. The first editor import in the fresh worktree failed while font cache resources were being imported; the second import completed cleanly, and the subsequent native capture had no errors.

At original game size, the longer alpha transition made path edges visibly eroded and green-speckled. The lower-coast path still contains clipped, thin strokes near the house, and the stairs approach remains angular. The candidate is worse than the baseline, so the runtime and test changes were reverted. See [lower coast, 667×375](../visual/land-route-solution-diagnostic-20261118/hub-lower-coast-667x375-ab.png) and [central stairs, 844×390](../visual/land-route-solution-diagnostic-20261118/hub-central-stairs-844x390-ab.png), baseline on the left and candidate on the right. The complete six-frame pairs and logs remain local under `artifacts/godot/route-solution-{base,candidate,comparison}-20261118/` and `.runtime/route-{base,candidate,import,import-2}.log` in the trial worktree.

The next effective pass needs a single coherent corridor mesh with authored tapers and world-space material variation, while retaining floor and connector ownership. Increasing per-piece alpha feathering creates speckle at overlaps; narrowing independent pieces breaks continuity; a broad opaque polygon union flattens the route. A new mesh must be checked at real game size and against path, stairs, and house movement before release. These native stills do not prove browser, Windows, or Samsung S23 frame pacing. Tools used: the project's Godot renderer and Node/TypeScript tests, Python Shapely 2.0.7 for offline polygon connectivity, and Pillow for comparison sheets. No external asset or licensed code was added.
