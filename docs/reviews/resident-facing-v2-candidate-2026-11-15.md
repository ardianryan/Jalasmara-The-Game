# Seven resident rear views, source candidate — 15 November 2026

The owner rejected the first side/rear release because villagers visibly changed identity on turns. Staging was restored to the accepted `f547723c0205` image. This second package replaces the rejected 12–17-color alternate silhouettes with source-matched rear artwork for Ki Lurah Wirabhumi, Mbok Ratih, Kang Tedi, Saras, Mbah Wira, Beno and Inspektur Raka. Front and three-quarter side keep the exact accepted source gait pixels; west mirrors the three-quarter view. Northward travel selects a true rear view. The four short rear foot poses are made from each static sprite with code; the phase still follows real distance and stops at idle. Schedules, collisions, dialogue, boss mechanics, economy and server state are unchanged.

The seven static rear sources were made with the built-in imagegen identity-edit tool from the seven project portraits, then visually curated. The generated output is **static source art only**. `tools/npc-rig/pack_facing_v2.py` crops nontransparent pixels, uses nearest-neighbor normalization to 64×64, snaps alpha, keeps the original front pixels, and moves two lower-body pixel regions through four step phases. High-resolution originals, reference identities, source SHA-256, prompt summary and project-art terms are in `assets/source-2d/resident-back-v2/manifest.json`. Runtime strips and hashes are in `client-godot/resources/art/npc-facing-v2/manifest.json`. No external sprite pack or tool code was included; Pillow 11.3.0 is an offline authoring dependency. Game art follows `LICENSE` section 2, separate from MIT source code.

The independent detail gate `tools/npc-rig/audit_facing_detail.py` checks five frames, quantized color variety relative to each front, height continuity, and changed rear gait pixels. The rejected v1 sheets score **0/14** (minimum detail ratios 0.052–0.089); v2 scores **14/14** (rear minimum ratios 0.631–0.950). This coarse metric catches obvious visual collapse; it cannot establish anatomical correctness or taste. A temporary source-preserving programmatic rear-head experiment was discarded after showing striped heads and visible front faces. It is not in the project.

Godot 4.7.2 Compatibility imported all 21 new PNGs. The focused `village-boss-motion.gd` test passed all seven rear resources and four distinct step resources while retaining boss phase, projectile, pause and recovery checks. Native `npc-simple-steps-render.gd` captured **105** actual 480×270 Sprite3D frames for the three views and five phases; the [curated sheet](../visual/resident-facing-v2-native-20261115.png) has SHA-256 `9eae6b44e4b0679f6e4753bb0dcf3fedcba33798ef26b3bcd388bba8cc492649`. The complete `npm run check:world`, `npm run typecheck` and `npm run build` passed. Local exported PCK SHA-256 is `941693674e10517f6a97c1e36d2576556e4cfd892e0347ace3a5a53f9510bc7f`. The first focused Godot invocation failed before import because the new PNGs had no imported resources; editor import and the rerun passed. No API source changed, so local API integration tests were not rerun; GitHub CI remains the authoritative API/build gate.

At the source-candidate checkpoint, this was **not yet a staging release**. The native sheet showed small but coherent sprites and no obvious detached feet in the five-frame rear comparison; it did not prove live route turns, Windows/Samsung S23 quality or frame pacing. The profile intentionally reuses the accepted front three-quarter view; it is not a new strict 90° side drawing. The director and five children still use separate one-view rigs. Delivery and remaining acceptance are recorded below.
