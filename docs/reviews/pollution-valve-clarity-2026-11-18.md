# Underwater valve pollution clarity — bounded candidate

Source branch `work/ocean-pollution-clarity-20261118c`, based on `928abf6`. This package changes only the underwater valve plume's existing 12 MultiMesh quads. Each bubble is moderately larger, its outer ring is thicker, and a faint center haze makes the purple source more legible. It adds no particle, draw call, collision, trigger, physics rule, damage, or state transition. The source remains anchored to the existing valve outlet. `PollutionBubbles.intensity()` still clears it after boss victory.

The original full-ocean screenshot fixture waited indefinitely for `RenderingServer.frame_post_draw` in an earlier attempt. A new focused native fixture, `scripts/tests/pollution-valve-camera.gd`, recreates the production ocean's orthographic camera, 12° tilt, 2,200-unit distance, 480×270 nearest-filtered SubViewport, and the same source/focus position without constructing the entire arena. It also uses **the real production valve atlas cell** with the same 140×135 Sprite3D dimensions, (+0,+82) offset, depth, nearest filtering, and directional light. It captures through `RenderingServer.force_draw(false)` at 667×375 and 844×390 root sizes. The [667×375 baseline](../visual/pollution-valve-camera-20261118/baseline-667x375.png) and [candidate](../visual/pollution-valve-camera-20261118/candidate-667x375.png) are original-size evidence; [844×390 baseline](../visual/pollution-valve-camera-20261118/baseline-844x390.png) and [candidate](../visual/pollution-valve-camera-20261118/candidate-844x390.png) show the same increase. The bubbles rise from the valve's left copper elbow in both viewports. Purple-pixel counts rose **515→1,046** and **726→1,415** respectively, using the fixture's fixed color threshold. After victory, the count is **0** at both sizes; the [667×375 cleared frame](../visual/pollution-valve-camera-20261118/after-victory-667x375.png) is retained. The source and target have 12 visible instances before victory and 0 afterward.

Native Godot 4.7.2 Compatibility on Apple M2 completed both A/B captures with no `SCRIPT ERROR`, `ERROR:`, or parse error. The existing headless `pollution-bubbles.gd` authority/anchor/budget regression passed. The first cold editor import crashed while importing assets; a second editor import completed cleanly before the native runs. `git diff --check` passed. The five selected PNGs total less than 20 KiB; SHA-256 values are available from `shasum -a 256 docs/visual/pollution-valve-camera-20261118/*.png`.

**Acceptance boundary:** the focused fixture shows the real valve sprite and bubbles, but not the larger connected pipe, boss, rock, coral, or full lighting/background composition. It establishes local outlet alignment, not whether the whole arena reads as one believable pollution source. It does not establish moodboard parity, browser frame pacing, or Windows/Samsung S23 acceptance. A source-exact in-world moving capture should be reviewed before staging. The plume remains a small cluster of rings rather than a large toxic cloud; increasing density would require a separate art/performance review.
