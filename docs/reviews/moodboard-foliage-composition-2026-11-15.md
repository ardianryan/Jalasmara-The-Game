# Foliage composition at game size — accepted as a bounded improvement

15 November 2026. The owner asked for foliage that reads more like the colorful, comfortable pixel-art moodboard while keeping clear paths, character occlusion, and a stable pixel grid. This isolated candidate is on `work/foliage-composition-20261115`, based on main `e061855`; it has **not** been integrated, pushed, exported, or released to staging. The change improves crown variety but does not establish full moodboard parity or physical-device FPS.

The existing `land-foliage-v1.png` atlas has six 512×512 cells. The forest map already labels 18 mangroves and 25 broadleaf trees, but the runtime rendered all non-palm crowns from cell 0. The renderer now uses its existing cell 4 for every second mangrove and every fourth other non-palm tree, at 92% of normal crown width with a mild dark-green tint. Palm trees and the tree positions are unchanged. The same number of Sprite3D crowns, atlas textures, materials, and occlusion registrations are emitted; no new art, asset transfer, collision, server map, or dependency is added. Nearest filtering and alpha-cut remain.

The first trial assigned cell 4 to all 18 mangroves. Native day comparison changed 19.85% of the 667×375 forest frame but repeated its lighter motif too often. A one-in-three assignment left the focal forest frame almost identical to baseline (0.2% changed pixels); it was rejected. The final alternating-mangrove version changes 12.39% of the 667×375 forest day frame and 11.71% at dusk, counting pixels whose maximum RGB difference exceeds 12. In the 844×390 hub view, one broadleaf near the house changes and the frame difference is about 3%. The alternate crowns are separated in the reviewed forest view; the bridge and path remain visible. These are composition improvements rather than a new source-art fidelity pass. Review the actual-size native [forest day/dusk pair](../visual/moodboard-foliage-forest-ab-20261115.png) and [hub day/dusk pair](../visual/moodboard-foliage-hub-ab-20261115.png). Their SHA-256 values are `61328295e7861bff46604d06414fcdb82f1b700e6d6c060ce6f77adaa4007d84` and `04904fe5a06eaac201f7bce472cf01cccf26fae62ce5c8f8d54530f77b47abf2`. The uncurated 16 full-resolution frames and `results.json` remain local under `artifacts/godot/moodboard-foliage-composition/`.

The wind helper now preserves wind direction while quantizing displacement to the pixel grid, and a focused test covers negative wind. `EnvironmentState` currently produces positive wind, so this is a directional correctness change, not a claim that current in-game gusts look different. Reduced-motion behavior is unchanged.

Godot 4.7.2 Compatibility rendered the 16 paired frames on Apple M2 with no `ERROR` or `SCRIPT ERROR`. The initial `--headless` attempt used the dummy renderer, returned a null viewport texture, and was discarded. The corrected native fixture sets both authoritative and presented clock values, producing visibly distinct day and dusk frames. `scripts/tests/land-renderer.gd`, `forest-readability.gd`, and `coastline-foliage.gd` pass; the existing forest readability test covers occlusion selection and restoration. `git diff --check` passes. The current fixture does not render a moving Nala through every crown, and it does not measure draw calls, browser GPU frame time, or Windows/Samsung S23 performance. Those remain integration acceptance checks.

Tools actually used: project Godot 4.7.2 Compatibility, Python 3 with Pillow 11.3.0 for alpha counts/contact sheets and RGB comparison, repository source inspection, and Git. No external image generator or moodboard pixels were used. The source atlas is an existing project asset governed by the repository's asset provenance and license records; the two new images are documentation captures, not runtime assets.

Integration order: cherry-pick the local commit, run the combined world/typecheck/test/build checks, then capture a moving forest character with occlusion and compare frame time on target devices before staging. If the merged scene makes the alternate crowns too bright or occludes Nala, revert this bounded runtime change rather than modifying the authored map to hide the issue.
