# Reef 12 visual seam diagnostic — 18 November 2026

Status: **diagnostic only; no runtime change accepted or released**. The isolated worktree `work/ocean-composition-parity` started at `1061b4a`. The issue is the nearly horizontal, dark block under the grounded valve in the deep side-view scene. At 667×375 its upper edge begins near Nala's height and continues to the right side of the frame; it reads as a rectangular slab rather than a reef face.

I used the existing full ocean fixture `scripts/tests/coral-rock-render.gd` with the same deep camera, weather, swimmer position and `balanced` quality at 667×375 and 844×390. The unchanged [667×375 baseline](../visual/ocean-reef12-diagnostic-20261118/baseline-deep-667x375.png) has SHA-256 `dad3fd68066a689ce36c61ffd504d1d14cb9ef8ab7323564cd2e8db790fc80d1`. Temporarily hiding only `ReefRelief12` exposed the teal backdrop and removed the rectangular block, identifying that mesh as the source. Disabling its shadow casting had no visible effect, so the dark face is not caused by a self-shadow. Increasing the rear face vertex tint also had no visible effect, so that face is not the visible area. Temporarily doubling `rock_tint` on the complete mesh changed the block, but the [667×375 result](../visual/ocean-reef12-diagnostic-20261118/rejected-bright-deep-667x375.png) became neon green and lost the deep-water atmosphere. That treatment was rejected.

A separate eight-facet coral-root trial increased the physical detail of each of 39 mounted coral contacts without another draw call. The focused headless `coral-rock-integration.gd` test passed and the unchanged and candidate scenes both captured four actual-size frames. At game size the result was imperceptible, so this trial was also rejected. No code from either trial remains in this commit. The original 43 coral pivots, 39 supported mounts, all terrain/collision contours, pipe source, boss mechanics, and gameplay data are unchanged.

The native baseline and temporary candidate fixtures reported no `ERROR` or `SCRIPT ERROR`; each reported unchanged oxygen 77 and coins 700. The first fresh-worktree editor import logged transient missing font-cache errors before the resources completed import; the later native passes succeeded. Ignored local raw A/B frames and logs are under `artifacts/godot/ocean-composition/` and `.runtime/ocean-*`. The deep 844×390 baseline SHA-256 is `0ca11389700be98e22e9894c2af11184e4e21ee2b891e9ec6f58f1554a9fbba2`; the doubled-tint frame is `f2bf985b13c3f5bd3683a819f72f54011fc4ffd1bc4d263a937817fa410b1d3a`. Native Apple M2 stills do not establish browser motion, Windows/Samsung S23 frame time, or full moodboard parity.

The first follow-up hypothesis was to reshape the **visible upper/front silhouette** of `ReefRelief12` with a small broken lip while leaving `WORLD.terrainContours[12]`, collision, server walkability and the valve location fixed. Existing project atlas and Godot 4.7.2 were the only tools/assets used. No third-party asset or moodboard image was copied into the game.

## Follow-up lip trial

A second source-only candidate inserted six raised points, each 8–17 world pixels, into `ReefRelief12`'s displayed upper contour while preserving every authoritative source vertex. `ocean-platform06.gd` passed with an additional bound/immutability check, and the full native fixture passed at both sizes with no script errors and unchanged resources. The [667×375 result](../visual/ocean-reef12-diagnostic-20261118/rejected-lip-deep-667x375.png), SHA-256 `d4724b4e8ac16b299f76c3f0ad95ac3b467f5645a138163ae63b0e25fffcea1f`, barely breaks the line; the broad dark rectangular face persists. The 844×390 candidate SHA-256 is `5604333f6c0c5c961f7e8e85082658ccd1c3f21dcc9b08dd4e7f8d02491f0130`. The trial was reverted. Its passing geometry test is **not** visual acceptance.

The structural cause is the source contour itself. `WORLD.terrain[12]` is a broad, shallow `1844×160` shelf at `(4300,2800)`; `coastalContour` supplies only four widely spaced points across its top and three across its bottom. `TerrainGeometry._build_reef` projects that entire contour into one continuous front face, so decorative tint changes, a small lip or added coral cannot remove the rectangular footprint. A meaningful redesign needs a jointly authored irregular terrain contour and corresponding collision/server verification, or a separate background-only mass that does not pretend to be the playable shelf. A renderer-only silhouette cut would expose water where the current server still blocks Nala. This diagnostic package therefore leaves the runtime unchanged and asks for a coordinated world-geometry package rather than another cosmetic patch.

## Shared-contour trial and rejection

I tried one bounded data correction after verifying that the server's `/api/dive/position` validation and Godot reef mesh both read `WORLD.terrainContours`. A 35-point contour stayed inside terrain 12's existing rectangle. A temporary CPU test checked positive screen-space winding, bounds, no crossing edges, JSON transport, server clearance at the valve and all six generated boss resonances, and a connected grid route from the cave approach to each point. Both focused tests passed. The six resonance points are at x=3380/3620/3860 and y=3060/3260, west of terrain 12; the valve is `(4660,2630)`, above it. The test established geometry safety at those positions, not visual quality or full gameplay acceptance.

Godot 4.7.2 Compatibility rendered the unchanged fixture at 667×375 and 844×390 with the same deep camera, `balanced` quality and gameplay resources. It exited without `ERROR` or `SCRIPT ERROR`; oxygen remained 77, coins 700, and all 43 coral pivots / 39 mounts remained present. The [667×375 candidate](../visual/ocean-reef12-diagnostic-20261118/rejected-contour-deep-667x375.png), SHA-256 `09791f853095b99a83efade6b0622ea58351f90ae66f47161d3ac3bc9feef18d`, removes the horizontal rectangle but replaces it with a broad dark zigzag face and sharp, synthetic notches. The 844×390 raw frame SHA-256 is `a4121bf5af637cd1b8f49c34903636d20175746e8a8278e3949956921d93b255`. This is **rejected** against the natural 2.5D reef target. Commit `48cfc85` contained the trial, and `6602890` reverted it; the world-map fixture was regenerated from the restored 13-point contour. `npm run typecheck` could not start inside this isolated worktree because its `tsc` executable was not installed there. No runtime contour/test change from this trial is intended for main.

The remaining visible problem is the single large, dark continuous extruded face. A viable next package needs a shaped rock volume and side-face texture/shading that read as joined geology at actual game size, with an authoritative matching swim contour and navigation tests. Simply adding more contour vertices changes the outline into angular peaks while retaining the opaque band. No further render iteration was attempted in this package.
