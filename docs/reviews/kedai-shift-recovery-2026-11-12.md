# Active kedai shift recovery after a dock reset

Date: 12 November 2026. The owner confirmed that Nala's body is now fully visible but WASD still does not move her, even after clicking the game and opening other menus. Read-only staging data showed an active Kedai Waras shift for the owner's current player version while the saved surface position was at the dock. `Main._service_movement_locked()` intentionally freezes the player for any active shift; the reset endpoint previously moved the player to the dock without addressing that shift. The shift UI did not reopen on a fresh load, so the owner could neither close it nor reach Mbah Wira. No owner credentials were used and no owner data was changed during this repair.

## Change and acceptance

Source `128fc592f9fe15cc2803a1a734a8200f39ee1422` on `main` reopens the Kedai service panel on load when a valid shift exists. If the player is stranded away from Wira, the panel explains recovery, retains **Tutup sementara · cari stok**, and cannot be dismissed into another locked state. The temporary close uses the existing server transaction; it preserves completed orders and does not advance the story day. A position reset during an active shift now chooses the safe Wira point in the hub instead of the generic dock anchor. Ordinary hub and forest resets retain their previous anchors. The shift itself is never silently deleted by reset.

The focused Godot `kedai-resume.gd` regression proves that the recovery panel remains available after repeated dismissals at the dock and normal stationary Wira resume still works. The API integration test covers an active shift with a stranded forest coordinate, reset to the Wira hub point, unchanged coins/progress/version and explicit temporary close. Local `npm run typecheck`, `npm test` **123/123**, `npm run check:world` and `npm run build` passed. Build and world logs had no `SCRIPT ERROR` or `ERROR:`; headless audio-driver warnings from unrelated SFX checks remain. Local MongoDB/Redis fixture services and their database directory were stopped and removed. Gitea [run 49](https://git.ppti.me/ardianryan/Jalasmara-The-Game/actions/runs/49) completed **success** on the source SHA.

The old public image reproduced the failure with a disposable `female_nusantara` account at dock `(1000,1200)` and an active shift: the service panel remained closed on load. The new image displayed the recovery panel automatically. The first new-build browser attempt pressed Enter on **Baca bukti lapangan** and failed only the test's incorrect button selection; its fixture was cleaned. The corrected Chromium/SwiftShader smoke clicked **Tutup sementara**, observed `shift: null`, unchanged 110 coins and story day 1, then held D: the player moved from `(1000,1200)` to approximately `(1072.3,1241.5)`. That fixture was also cleaned with zero remaining players or shifts. [Before close](../visual/staging-shift-recovery-active-20261112.png) and [after movement](../visual/staging-shift-recovery-moving-20261112.png) are original project screenshots from this disposable browser test. This proves the release flow in a desktop browser, not the owner's existing session or physical Samsung/Windows performance.
