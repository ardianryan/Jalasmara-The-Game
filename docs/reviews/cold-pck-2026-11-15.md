# Public PCK tail latency: bounded head-of-line hedge

## Scope and observation

This branch changes only the segmented PCK loader and its focused tests. The active staging PCK was not replaced and no browser, GPU, or account-backed gameplay test was run here. The previous cold Chromium trace for PCK `c7c40eab9ecef4abcb56dedde18cd473a95881c77acb124186d5cd76661b0fb4` stopped at 38% after 120 seconds; the warmed browser smoke later passed 6/6. Those results are documented in [the release report](ocean-backdrop-alpha-edge-2026-11-15.md).

Read-only public probes on the already-warmed PCK still showed long individual 1 MiB tails. With four independent `curl --http2` connections and cache-busting query strings, three parts finished in 0.065–0.176 seconds while one took 6.812 seconds. With six connections, four finished in 0.072–0.117 seconds and two took 6.437 and 11.389 seconds. HTTP/1.1 had similar outliers: four requests included 4.55–9.56-second parts; six included 7.68 and 9.82-second parts. These are public-path observations, not a controlled cold-browser comparison, and they do not identify the nginx/provider fault. The public hostname resolves through `myrephost.ppti.me` (`45.198.149.181`). In contrast, a read-only probe from the app VPS to its private Fastify endpoint (`10.1.0.8:3000`) fetched twelve 1 MiB parts in 0.003–0.083 seconds each. The application source already sends exact `Content-Length`, offset, total length, and immutable cache headers.

A separate ad hoc Node HTTP/2 24-part probe produced no bounded result and was stopped after more than 90 seconds; it is not evidence of a successful or failed browser startup. Its temporary script is ignored under `.runtime/` and is not part of the change.

## Change

The Godot loader continues to prefetch four parts and yield them in manifest order. When the **next part blocking the stream** has not verified after 1.5 seconds of waiting, it starts one additional request for that same part using a distinct query URL so the browser does not coalesce it with the stalled request. At most four primary requests plus **one** hedge can be in flight. The first fully verified response wins; the loser is aborted. Every candidate still needs HTTP 200, exact length/offset/total headers, exact body length, and the manifest part SHA-256 before any bytes are delivered. Overall identity is published only after every ordered part reaches the consumer. WASM and other assets keep their existing fetch path and the visible progress remains based on delivered bytes.

The maximum added request count is one per blocked part and one at any instant. A pathological 70-part PCK could cause at most 70 additional 1 MiB requests; typical fast parts start none. The exact duplicate bytes consumed on the public network are **unknown** without a browser network trace. The synthetic stalled-part test has one duplicate, zero primary body bytes before abort, and one aborted loser; the both-stalled test proves five total started requests (four primaries plus one hedge) and five aborted signals. Do not infer real wasted bytes from these fixtures.

## Verification and release gate

`node --test scripts/pck-stream.test.mjs scripts/pck-identity.test.mjs scripts/godot-preloader-stream.test.mjs` passed **25/25**. `npm run typecheck` passed using the main worktree's dependency directory as a temporary symlink; the symlink was removed. `git diff --check` passed. No Godot import/export or browser runtime was used in this worktree. Tooling: Node built-in test runner, curl 8.7.1, Fastify endpoint read only; no new asset, third-party dependency, or license.

Before accepting or staging this change, the integrator must export a new PCK SHA, run a genuinely cold public Chromium startup **before prewarm**, capture transfer start/end, duplicate count, aborted requests and transferred bytes per segment, then repeat the same path after prewarm and complete the six public smoke checks. Compare the bounded 120-second ready result with the old 38% trace. If cold startup still fails, retain that status; the hedge only mitigates a subset of tail latency and does not repair the underlying public proxy or reduce the 73 MB PCK size. Test on Windows and Samsung S23 separately; SwiftShader/Chromium timing is not device FPS.
