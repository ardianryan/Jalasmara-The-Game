# Underwater depth-composition trial — rejected

The owner reported that the coral does not sit naturally in the rocks and the underwater view lacks 2.5D depth. This isolated trial addressed only the rear atmosphere in `OceanBackdrop.gd`; the separate coral-to-rock pass owns the foreground attachment. The source base was `be58e0b`. No runtime change from this trial is retained or released.

I temporarily reduced each far-plane rock card from 1760×1530 to 1360×1150 world units, moved its first band from Y 1140 to Y 1030, and tightened horizontal spacing from 1450 to 1300. The existing 48-card, three-plane parallax budget, water shader, side-view camera, gameplay and collision were unchanged. This brought the rear silhouettes into a smaller scale, but it also exposed a wider, plain teal swim lane. At 667×375 and 844×390 the result did not improve the relationship between the painterly rear limestone and the crisp playable reef/coral enough to justify a runtime change. The candidate source and temporary diagnostic fixture were reverted.

Hashes above are SHA-256 prefixes of the committed PNGs. The first candidate capture omitted Nala although fish and scenery rendered. A subsequent candidate run showed Nala at both sizes. A temporary fixture asserted that `OceanActors` held a visible player `Sprite3D` with a texture at all four capture points, including reef and passage; it passed. The cause of the first omission is **not established**. It must not be dismissed as a known warmup issue or used as evidence that the candidate is safe. It is one more reason to reject this trial.

The project Godot 4.7.2 Compatibility binary on Apple M2 generated four baseline, four first-candidate and four diagnostic candidate native screenshots at 667×375 and 844×390, reef and passage; all three render runs exited 0 with no `SCRIPT ERROR` or `ERROR` in those run logs. The first editor import in this fresh worktree printed transient missing font-cache errors before import completed; no clean editor re-import is claimed. This is native still-frame evidence, not browser, Windows, Samsung S23, motion or GPU frame-time proof. No external asset/tool was added. The only art examined was the project's own generated `ocean-atmosphere-atlas.png`, whose provenance remains in `docs/assets/ocean-atmosphere-prompt.md`.
