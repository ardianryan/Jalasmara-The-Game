# Foliage source-quality trial — rejected

The owner wants clearer, more deliberate pixel foliage at the actual game scale. This isolated branch tested a source-local sharpness pass against the project's existing six-cell foliage atlas. **No runtime artwork, shader, UV mapping, renderer, or build asset changed.** The candidate is rejected: it is visibly different in the forest, but its lime highlights and dense black-green microcontrast make the tree look noisier rather than closer to the approved moodboard. The hub view barely changes. A numerical difference alone is not a quality result.

The production atlas `client-godot/resources/art/land-foliage-v1.png` remains 1536×1024 RGBA, 2,363,421 bytes, SHA-256 `1f07437f9ff5f9cbc063c191904eecf734ffad859b3daf6f0fccf177c8aa4564`. The rejected candidate retains all six 512×512 cells and the **identical alpha plane**, and uses only original project RGB pixels. Pillow 11.3.0 applied contrast 1.09 and a radius-5, 110% unsharp mask with threshold 8 to opaque leaf interiors; editing fades to zero over alpha 170–235 to avoid changing translucent silhouette pixels. The candidate (not committed as an asset) is 2,484,324 bytes, SHA-256 `36fce4b1f1301b1fbad7695c65e95d19f37f410081c89f4d787aa8cdbc27acc7`. No third-party or moodboard image was copied. The source atlas remains under its existing project asset provenance and license; the trial adds no dependency or notice to distributed code.

Godot 4.7.2 Compatibility on Apple M2 rendered the same live land map, camera, clock, and 3D scene at **667×375 and 844×390**. The temporary native fixture swapped only the atlas texture on the same Sprite3D nodes: 136 in the forest and 53 in the hub. The [actual-size 667×375 side-by-side](../visual/foliage-source-sharpen-rejected-20261115.png) shows the forest tree before and after without upscaling. At 667×375, RGB differences greater than 16/255 affected 3.349% of forest pixels but only 0.222% of hub pixels; at 844×390 the figures were 2.749% and 0.187%. The forest silhouette remains intact, yet highlights become harsh and tightly speckled. This does not solve leaf-cluster readability. There is no measured browser or physical-device FPS, and this rejected candidate was not built or staged.

The first fresh-worktree editor import emitted a missing font cache error while creating imports. A second import had no `SCRIPT ERROR` or `ERROR`; the native render log also had none. Raw frames and the temporary fixture were removed with the completed worktree; the curated contact sheet remains documentation, not a game asset. The contact sheet SHA-256 is `053ce6a5fbf53505408467032cbe46f8b051bb458f98be39261fde5f4b8e832d`.

The earlier 96×96-per-cell downsample was also rejected because it changed almost no rendered pixels. Together, these tests show that generic pixel reduction and generic sharpening are insufficient. Next foliage work should author a few larger, intentional leaf masses and branch gaps directly at the displayed canopy size, then compare silhouettes across day/dusk/night and at both viewport sizes. Keep the current 3D sprite count, occlusion behavior, and original art provenance until such a candidate passes visual review.
